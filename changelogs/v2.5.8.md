## v2.5.8

fixing the "it says spoofed but nothing actually replaced in studio" bug, plus cleaning up a bunch of warnings that were confusing testers.

### Fixed

- **animations were only getting half-replaced.** roblox added a newer property called AnimationContent on Animation objects on top of the classic AnimationId. the runtime reads whichever one is set, so patching only AnimationId left AnimationContent still pointing at the original asset. character plays the un-spoofed animation and it looks like nothing happened. the plugin now scans both and the daemon patches both.
- **"a Animation" grammar in the placeholder-image error message.** says "an Animation" now.

### Changed (clearer warnings and errors)

- **"successfully resolved metadata for 0 assets" is no longer a lie.** if the batch endpoint gives back nothing, it's a red flag not a success, and the warning now says what to check.
- **partial batch results say what's missing.** was silently reporting 254/412 URLs as a plain "success". now it says how many fell back to per-asset resolution.
- **"blocked by roblox" is more specific.** 409 conflict from asset delivery actually means your account or forced Place ID doesn't have permission -- that's what it says now.
- **"error decoding response body" is human-readable.** translates the reqwest jargon into "roblox cut the connection mid-download, retries didn't recover, try again in a moment."
- **"auto-replacement queued!" is honest.** now includes the count and mentions the plugin has to be loaded in studio for the swap to actually apply.

### Added

- **auto-triage on jobs that mostly or entirely fail.** if 100% of assets fail, the app now tells you the 3 most common causes (refresh the cookie, pick a Place you own for forced Place ID, matching Open Cloud API key) instead of leaving you with a wall of red warnings. same idea if over half fail.
- **flag when uploads succeed but no replacements got queued.** that's an internal-bug scenario and it used to be silent. now it says so.
