## v2.5.11

Big bundle: fixes the "plugin says it applied patches but nothing actually replaced" bug, makes memory injection + plugin bridge work TOGETHER instead of one-or-the-other, stops the whole spoof job dying when Studio isn't connected, and clears up a pile of confusing warnings.

### Fixed
- **Plugin patches sometimes silently no-op on Content properties.** The scan side accepted values for any known asset property, but the patch side only knew how to encode a `Content` value when reading back the current property succeeded AND `Content.fromUri` was available in that Studio build. If either failed, coerce fell through and tried to assign a raw digit string to a Content property -- Studio silently rejected it, no error, no replacement. Now there's a property-name lookup for every known Content-typed field, tries `Content.fromUri` then falls back to `Content.new`, then a raw URI string as a last resort. Also handles number-typed asset properties (HumanoidDescription body parts, PackageLink) explicitly.
- **Memory injection was disabling the plugin bridge entirely.** Turning memory injection on used to route all mappings through it only, but memory injection can only patch length-matching id pairs (10-digit old + 15-digit new never fits). Those length-mismatched pairs got dropped silently with no fallback. Now both run: memory injection first for what it can do, plugin bridge for everything else. Together = 100% coverage.
- **Spoof job died when Studio wasn't open.** The upload half of spoofing doesn't need Studio at all -- just the final apply step. Previously the whole run threw and lost the mapping table if Studio wasn't running. Now the mappings are saved BEFORE the apply attempts, and if Studio's offline the log tells you the mappings are ready and how to apply them later (open Studio + Retry Replacement, or copy IDs from the Results panel).
- **"Click Run Spoofer, nothing happens".** Silent early-returns (missing cookie, invalid cookie, no valid IDs) now write a persistent line to the logs panel in addition to firing a toast, so the log tells you exactly WHY the click was a no-op instead of leaving it blank.
- **Dedupe-skipped assets were counted as fresh successes.** Assets that hash-matched to a previous run were recorded as `{success: true}` with no reason. Now they show up in the new Skipped & failed section of the Results panel with "Already uploaded in a previous run".

### Added
- **Batch pre-warm of creator info.** Discovery used to do a serial `/v2/assets/{id}/details` fetch per unique creator to learn who the creator is. We were already calling `/catalog/items/details` (batch, 120 assets at a time) for metadata, and that response carries the same creator info. Now we seed the discovery cache from it -- one less HTTP hop per creator on every job.
- **Fast-fail on auth-empty batch responses.** If both batch metadata AND batch download-URL calls return zero for the whole asset list, the job aborts in ~2 seconds with an actionable "your cookie/place/API key is broken, check these three things" message instead of grinding for a minute through per-asset failure paths.
- **Explicit halt message when the Open Cloud API key gets rejected.** A 403 on upload halts the queue (correct behavior -- no point continuing with a dead key), but it used to be silent. Now it says so clearly and points at the Creator Dashboard settings to fix.
- **"Skipped & failed" section in the Results modal.** Every asset that didn't spoof shows up with its type, name, id, and specific reason. Failed entries in a red-tinted card, skipped in the neutral card. Header has a "Retry N failed" button that resubmits just those assets and closes the modal.
- **Diagnostic log lines** for the Studio scan pipeline: `Studio scan finished: N records collected, N pending mappings, N patches planned.` and `Studio plugin applied N/M patches (failed: N).` -- makes it possible to see exactly where a job loses assets when something goes wrong.

### Changed
- **Bail-on-consecutive-failures raised from 5 to 20.** The old threshold was too eager and could bail before discovery even got a chance to add candidate URLs. 20 gives every asset up to ~40 URL attempts across direct and discovery phases before giving up -- caps worst-case at ~30s per bad asset while still matching v2.1's "try everything" behavior for accessible ones.
- **Internal `queue_replace_mappings_internal` now signals scan-required.** The HTTP `/replace-ids` path already set the scan-request flags when Studio had no records yet; the internal Rust path didn't. Fresh Studio sessions could receive mappings but never scan, so patches never got planned.
