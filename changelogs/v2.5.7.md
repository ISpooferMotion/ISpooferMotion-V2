## v2.5.7

Fixes the "some replacements silently don't happen" bug, closes the "spoofing produced images in place of animations" hole, and cleans up a pile of adjacent asset-pipeline issues.

### Fixed
- **Successful spoofs sometimes weren't being replaced in Studio.** A race in the plugin bridge: when the spoofer finished before the Studio plugin had scanned the place, the daemon *drained* the pending mappings when the plugin polled for them (even though the plugin's contract is to ignore mappings-only responses and wait for patches). When the plugin's scan finally landed, the mappings were already gone, so no patches got planned and every replacement was silently lost. Fixed by keeping mappings on the server until they can be delivered alongside patches.
- **Animations sometimes got "spoofed" with random image asset IDs, breaking Studio.** When Roblox refused a download for an inaccessible animation, it served a placeholder PNG. The uploader auto-retyped it as Image, uploaded it, and Studio ended up with an image asset id pasted into an AnimationId slot. Now: only Mesh → Image auto-retype is allowed (that one's a legit case where mesh slots hold decal URIs); any other type-vs-payload mismatch fails cleanly with "Download returned a placeholder image, likely refused access" instead of poisoning the replacement map.
- **Plugin scan wrongly categorized `MeshPart.TextureID` as a mesh.** All-caps `TextureID` is a texture asset, not a mesh. It was going into the mesh bucket, so users spoofing "meshes only" would find image IDs mixed in. Moved to the image bucket.
- **`contains("id")` catchall was sweeping unrelated IDs into the image bucket.** Attributes and StringValues named `PlayerId`, `BadgeId`, `TeamId`, `MatchId` etc. were all being categorized as image assets. Removed the catchall so unnamed/miscellaneous IDs stay unknown instead of being wrongly typed.
- **"error decoding response body" killed the asset outright with no retry.** When Roblox cut a streaming download mid-body, the error bubbled straight out with no retry, no fallback URL, no discovery. Now treated as a transient transport error: same 3-attempt / 1s+2s backoff as any other network hiccup, then falls through to the next candidate URL.
- **Discord release announcement fired twice per version.** Push to `main` triggered `SHOULD_RELEASE=true` (creating a release), and the follow-up tag push triggered it again, and both fired the announce step. Announce is now gated to tag pushes / manual dispatches only, which is the canonical release trigger.

### Changed
- **Discovery now runs as a fallback, not upfront, when a place ID is supplied.** Previously v2.5.6 skipped discovery entirely if the caller gave a place ID (fast path). But if that place ID didn't have access to a given asset, there was no recovery. Now: try direct URLs from the supplied place ID first, and if every one fails, run discovery and try those URLs. Best of both -- fast when it works, recoverable when it doesn't.
- **Group-owned asset discovery now walks the group owner too.** When the asset creator is a Group, the graph search now also crawls the group's *owner* (their personal games, their other groups' games, their friends) instead of stopping at the group's own game list. Catches assets that live in the human's account behind a group.
